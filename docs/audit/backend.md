## 范围与调用关系

逐行阅读了下面列出的 19 个后端模块，共 4,825 行项目源码；随后完整阅读并修改了 `tools/bench.py` 的 107 行与 `tests/e2e_local.py` 的 324 行。还交叉阅读了相关单元、集成测试及 Web/CLI 调用点。这个数字表示人工阅读范围，不是测试覆盖率，也不代表对第三方代理核心、操作系统或密码库作出了无漏洞保证。

管理接口、会员注册、节点同步和后台作业共享一个 SQLite 连接与进程内锁。配置生成器把账户及协议设置写给 Xray、Hysteria 和 sing-box；订阅生成器把对应凭据交给客户端。核心统计再由后台作业汇总到账户，限额状态经过配置重载作用到核心。主服务器还向子节点推送账户快照，并把子节点累计计数的增量计入本地。

因此，重点审查了四种边界：身份与 TLS 信任；先检查后写入的事务；统计增量与检查点的一致性；数据库、配置文件、核心进程之间的状态变化。另行检查了测试是否真的经过代理，以及异常能否使 CI 失败。

## 已确认并修复的问题

严重程度按实际影响与触发条件评估。需要节点密钥、管理员恢复权限或本机故障才能触发的项目，不能解释成匿名远程漏洞。

### B01 — 非法或缺失账户快照会删除节点已有账户（高）

位置：`cluster.py:79`，`handle_sync`。原实现把缺失/空值视为空列表，逐个跳过无效账户后仍据“本次收到的 ID 集合”清理节点用户。损坏请求或单个坏 UUID 因而能造成账户丢失；中途数据库错误还会留下部分更新。

修复：必须显式提供列表；先完整验证正整数 ID、重复 ID、UUID、密码、名称、开关与主身份，再在一个 DB 事务内增改删。只有成功提交才触发核心应用。绑定后的主身份冲突保留原冲突响应；结构错误为 `ValueError`，由 Web 映射为 400。旧测试的“默默跳过坏用户”期望改为“拒绝整个快照且无变更”。

验证：`ClusterState.test_malformed_snapshot_never_deletes_existing_accounts`、`test_node_update_failure_rolls_back_whole_snapshot` 以及原节点同步集成测试。

### B02 — 省略主身份可绕过已有节点绑定（高，需要节点密钥）

位置：`cluster.py:79–88`。原比较仅在请求带 `master_id` 时生效。掌握节点密钥的另一请求可省略该字段，覆盖受绑定保护的账户快照。

修复：节点已经绑定时，传入身份必须与持久化身份完全相同，缺失同样拒绝；锁内重新读取当前设置。未绑定节点仍保留旧版本首次同步兼容。

验证：`test_bound_master_cannot_be_bypassed_by_omitting_identity`。

### B03 — 空指纹节点连接先走未经验证的 TLS（高）

位置：`cluster.py:137–169`，`_request`。原程序总先使用 `CERT_NONE`；只有已有非空 pin 且不匹配才回退 CA 验证。没有 pin 时，账户和节点 bearer key 会发送给任意证书的对端。

修复：无 pin 只允许正常 CA/主机名验证；有 pin 才使用指纹通道，并在发送任何认证头/账户数据之前检查对端叶证书。证书续签后允许 CA 验证成功的回退路径。加入码校验类型、URL、用户信息、端口、密钥和 pin；响应限制 8 MiB，拒绝超长或非对象 JSON。

验证：真实 loopback TLS 测试同时覆盖正确自签 pin 成功、无 pin 自签失败，并断言失败请求未绑定主身份。

### B04 — 流量入账与远端检查点分离提交导致重复计费（高）

位置：`cluster.py:186–224`；`db.py:319`。旧实现先累计用户流量，待所有服务器完成后才保存 `seen`。第二台服务器出错、进程退出、检查点写失败，都可能让第一台服务器的相同增量在下轮再次入账。

修复：每台节点的流量增量、历史及对应检查点同事务提交；提交前重新读取节点记录，避免覆盖其间的删除、编辑或账号替换。同步结束不再把整份旧节点列表覆盖回设置。数据库故障完整回滚，账号不存在时不插入孤儿历史。

验证：故意让保存检查点失败，断言用量与检查点均未变化，再重复请求两次，累计只增加一次。历史表触发器抛错时也验证用量回滚、连接可继续使用。

### B05 — 仅凭计数降低检测重置，会漏掉已追平旧值的重置（中）

位置：`cluster.py:199–207`；`db.py:292`。如果子节点把累计值归零后已经产生更多流量，新计数高于旧检查点时，旧算法仍按普通差值计算。

修复：账户新增 `traffic_epoch`，绝对替换用量时递增，普通入账不递增；节点响应增加可选 `traffic_epochs`。主服务器同时比较 epoch 与节点本地账户 ID。旧节点不提供该字段时继续使用旧的“计数下降”兼容路径。远端计数、ID、epoch 必须为有界非负整数，不能通过负值冲减用量。

验证：重置后新计数高于旧值、普通计数更新不增 epoch、负计数拒绝、检查点重复同步。跨仓库客户端不消费这些内部字段。

### B06 — 多步数据库操作与会员锁不在同一事务边界（高/中）

位置：`db.py:209,225,266,310,319`；`members.py:32,115,182,240`。单个 SQL 调用的锁不能保证“检查名额→创建账户→消耗邀请码→事件”整体成功；中途失败能留下免费账户或半次操作。不同层的锁也不能统一保护管理员操作。

修复：提供共享可重入 DB 事务与嵌套 SAVEPOINT；会员检查与修改使用同一事务；设置批量写入、密钥初始化、用户插入附加字段、删除清理与流量历史均原子完成。新增账户在事务内执行与登录一致的 NOCASE 名称唯一性检查。

验证：邀请码最后一次使用由四线程竞争仅一人成功；消耗邀请码故障时账户不残留；嵌套事务回滚；大小写同名拒绝；用户附加字段错误不产生部分账户。

附加配额修复：`members.py:90` 的可分享额扣除 `max(最低保留总额度, 邀请者已使用额度)`，而不是只扣固定 1 GiB。10 GiB 账户已用 8 GiB 后最多再分配 2 GiB；兑换邀请时重新检查，避免邀请码创建后消费的流量再次被赠送。可分享额向下保留三位小数，避免显示舍入制造额外额度。另修复耗尽子账户后的自动退款：活跃子账户保留完整 grant，停用/到期子账户只返还未使用部分，保留其自身已消费金额及后代仍承诺/已消费的金额，最多计至原 grant。采用一次用户快照建图和迭代后序计算，不逐层访问 DB，不依赖递归；深链回归覆盖 1,500 层。零消费暂停仍返还全部赠额。R01 保留历史周期与管理员变更的边界说明。

### B07 — 恢复缺少原子性、身份/关系验证和会话失效（高，需恢复权限）

位置：`db.py:449–488`。原备份不含日流量历史，旧格式恢复可留下与新用户 ID 关联的旧历史、邀请码或申请；旧管理/会员会话也未统一废除。恢复中途失败可能损坏当前数据。只校验 JSON 顶层类型也不能阻止非法 UUID、ID 0、异常日期、损坏的嵌套服务器状态进入运行数据库。

修复包括：

- 事务快照导出用户、设置、邀请码、申请及可选日流量；维持原 `vps2vpn-backup-1` 标识。
- 恢复先验证全部表，失败整体回滚；明确字段白名单、类型、有限数、整数范围；拒绝正身份缺失、UUID 错误、NOCASE 重名、重复 UUID/远端 ID。
- 约束重置日 0–28、设备上限 0–100、首次使用期限 0–3650 天、开关及可表示时间范围；流量/申请须关联实际用户，邀请关系不能自指、悬空或成环。
- 检查嵌套服务器 URL/TLS、协议字段、ID 映射、流量/epoch 检查点，以及月统计、线路报告、域名列表的运行所需形状。
- 旧备份缺少可选表时清空旧关联数据；旧用户缺 ID 时分配有效且唯一的 ID；兼容设置布尔值 0/1 和用户 enabled 布尔值。
- 成功恢复清除全部管理及会员会话。保留合法历史：已用/撤销邀请码及 `used_by` 中被删除的用户 ID 不应误判成活动关联损坏。

公共设置的业务验证及恢复后密钥补全由 Web 恢复流程执行；数据库层不替代完整的核心配置验证。嵌套健康遥测不逐一限制所有未来扩展字段，生产备份仍应来自可信来源。

验证：事务故障、历史往返、旧格式、会话失效、身份与范围、孤儿记录/邀请环、损坏服务器检查点、旧布尔表示与删除后的邀请历史等回归。

### B08 — 固定临时文件名导致并发发布冲突（中）

位置：`paths.py:52–70`。所有写入者共用 `目标.tmp`，并发写同一路径可覆盖对方内容或在重命名后得到不存在的临时文件。单次 `os.write` 还不保证处理完整载荷。

修复：在目标目录创建独占的唯一临时文件，完整缓冲写入、flush/fsync、设置权限/属组后 `os.replace`；失败只清理本次临时文件，保留旧目标。

验证：六线程同时完成写入后在 rename 处同步，最终文件必须等于某个完整载荷；失败 rename 不破坏旧文件且不泄漏临时文件。此保证是单文件原子发布，未声称父目录 fsync 或断电后任意文件组的事务持久性。

### B09 — 协议重新启用但配置没变时不启动；systemctl 失败被当成功（中）

位置：`cores.py:114,163`。旧流程只在配置变化/force 时重启，停用后再启用相同配置可能保持停止状态；忽略命令退出码会报告已成功应用。并发应用还共用同一校验文件。

修复：整个生成/校验/启停流程串行化；已启用但进程不活动时启动/重启，即使文件相同；检查 systemctl 返回码并聚合报告错误，也报告跳端口配置失败。

验证：未变配置的停止核心被重启；模拟 systemctl 失败必须抛出可见错误。单个核心拒绝配置时继续保留该核心旧文件的已有策略不变。

### B10 — 只按 IP 匹配私网规则，域名目标可跳过检查（高，需有效代理账户）

位置：`cores.py:26–55,87–111`。Xray `AsIs` 不主动为 IP 规则解析域名；TUIC 的规则也没有先解析域名。把私网地址写成域名时，声明的私网拒绝规则不能覆盖同样的目标。

修复：Xray 使用 `IPOnDemand`；sing-box 在私网拒绝规则之前显式 `resolve`，设置本地 DNS 与默认解析器，已验证可达的 DoH 可覆盖默认服务器。

验证：配置属性回归；真实 E2E 增加三协议 × 两客户端对 `127.0.0.1` 与 `localhost` 的拒绝检查。每组先证明公网代理成功、私网目标直接可达，再通过 `http.client` 显式访问代理，记录目标是否真的收到请求，避免 `NO_PROXY` 绕过。E2E 使用本地解析器让 localhost 可确定解析，保留生成器的实际拒绝规则。

这仍不是针对所有 DNS 重绑定、多地址响应、IPv4 映射地址、系统代理及未来核心版本的形式化证明；应继续在目标系统上验证这些路径。

### B11 — TUIC 暂时采样失败后重计、采样乱序与余数丢失（中）

位置：`cores.py:225–297`；`jobs.py:551`。原代码把任何超时视为重启，清空连接基线；下一次成功会把仍存活连接的累计字节再记一遍。并发 poll 在锁外完成，响应顺序不一定是时间顺序。按比例逐项取整会丢失小额余数，删除用户的旧权重仍可参与分配。

修复：poll 与状态更新受同一锁保护；暂时失败保留基线；确实观察到总计数下降才重置连接/权重状态；已待交付的累积值保留。分配使用整数商及最大余数法守恒，清理已删除用户权重，采样使用所有现存用户，避免“只有一位启用用户”时错误归给他。

验证：100→暂时超时→150 仍只计 150；两个用户合计 201 字节不丢最后一个字节；删除用户不再吸收余数。

边界：核心只暴露全局总计和当前连接，采样间开始并结束的多用户短连接无法精确归属。比例分摊仍是估计；不应作为精确计费账本。

### B12 — 证书文件与状态边界（中）

位置：`certs.py:55,93,118,235`；`subscription.py:21`。

修复：自签缓存必须同时有证书、私钥和匹配主机标记，缺私钥重新生成；用上下文管理器关闭标记/PEM 文件；IPv6 SAN 以规范地址比较；指纹明确取 PEM 的第一张叶证书，避免 fullchain 产生错误 pin。签发过程串行化，最终证书/密钥发布、选择与读取受可重入证书锁保护；慢速 ACME 请求不持有 TLS 读锁。Web 的 TLSContext 也按同一锁顺序读取/加载。HTTP-01 挑战绑定仅在 IPv6 不可用的 EAFNOSUPPORT/EADDRNOTAVAIL 时回退 IPv4；端口已占用不被吞掉。

订阅 `tls_info(s)` 与面板使用同一证书来源；后续统一以 `domain or public_host` 作为证书身份，允许连接地址与 SNI 分离。只有在目标确实是同一 TLS 终结点时，客户端才能把订阅中的叶证书指纹用于面板认证。备用 IPv6 地址、独立域名或外部反代不能不加判断地复用该假设。

验证：删除私钥后生成可被 SSLContext 加载的匹配证书对；等价 IPv6 SAN；fullchain 指纹等于叶证书；真实 pinned TLS 同步；mock socket 验证两类 IPv6 不可用错误回退与忙端口不重试。

锁只保护同一个 Python 进程的读写者。两个文件仍分别替换；独立核心进程读文件时的窗口、进程外更新、机器断电、完整 ACME 公网挑战并未因此获得文件组原子性保证。

### B13 — 公网地址自动发现关闭 TLS 且未验证返回内容（高/中）

位置：`system.py:226`。旧公网 IP 探测使用未验证上下文；结果可能进入自动 IP 跟随和订阅，网络攻击者有机会影响发布地址。

修复：使用正常 CA/主机名验证；读取上限 4096 字节；只接受相应地址族的全局可路由 IP，拒绝主机名、私网及无效文本。

验证：检查上下文 `CERT_REQUIRED`/`check_hostname`，拒绝不合规结果；既有连续两次观测才更换地址的测试保留。

### B14 — 多服务器名称与固定分组撞名；共享配额头高报（中）

位置：`subscription.py:58,98,227,336`。服务器标签、派生协议标签、固定 Auto/AI/Proxy/中文分组原先没有统一命名空间；例如服务器叫 Auto，会生成冲突组或错误引用。共享后真实限额已降低，订阅头仍报告原配额。

修复：固定策略名、服务器分组、协议节点共用唯一命名空间，必要时稳定加序号，清理跨格式有结构含义的逗号、等号与空白；订阅头使用实际有效配额，有限零余额不能以 `total=0` 冒充无限。注释中的用户名去掉换行。

验证：跨服务器、派生协议和保留组名冲突；Clash 所有引用可解析、sing-box tag 唯一；10 GiB 账户赠出 3 GiB 后头中是 7 GiB。

### B15 — 测速工具把含凭据订阅当成非敏感内容，默认跳过证书验证（高）

位置：`tools/bench.py:31–40`。下载内容包含真实代理密码/UUID，订阅 URL 还带 bearer token。旧代码无条件 `_create_unverified_context`，并在注释中错误地称其不含秘密，且响应无大小边界。

修复：默认 CA 与主机名验证；支持 `--ca-file` 指定私有 CA；明文 HTTP 或关闭验证必须明确 `--insecure`，两参数互斥。仅允许合规 HTTP(S) URL，拒绝用户信息、片段、控制字符、非法端口；重定向仅同源。响应/本地配置读取限制 8 MiB，校验 proxies 列表及唯一名称；`--config` E2E 路径继续工作；强杀后 wait 回收子进程。

验证：真实自签 HTTPS 默认失败、明确 CA 成功；默认上下文、显式 opt-in、URL/重定向、精确大小边界、损坏 proxies、本地文件模式等。

### B16 — E2E finally 中退出可吞掉异常，代理绕过与失败诊断也不可靠（中）

位置：`tests/e2e_local.py:56,74,82,286–324`。原 `finally: sys.exit(...)` 覆盖未捕获异常，若异常前没有记录失败，进程会返回 0。失败详情传列表时，字符串拼接又触发 TypeError。urllib 的代理处理还会受环境 bypass 配置影响。

修复：清理与最终退出分开，未捕获异常保留 traceback、非零退出及日志；结构化 detail 转为文本；测速子进程 stdout/stderr 留档并检查 returncode。真实流量和私网探测直接连接本地 HTTP 代理，不受 `NO_PROXY` 影响；关闭日志/响应句柄，kill 后 wait。

验证：runner 异常/记录失败/成功三个分支；列表诊断；模拟拒绝代理和真实转发代理，前者通过安全探测，后者必须失败，即使 `NO_PROXY=*`。这验证了测试本身能发现绕过，而不只是检查生成配置。

### B17 — 全部用户停用时 Hysteria 配置为空并反复崩溃（中）

位置：`cores.py:57–65`。固定版本 Hysteria 2.14.0 的 [fillAuthenticator](https://github.com/HyNetworks/hysteria/blob/app/v2.14.0/app/cmd/server.go#L1485-L1491) 明确拒绝空 userpass。新安装、删除最后用户、全部到期/超额后均可能进入该状态，造成无意义重启和健康告警。

修复：空用户态保留一个仅内部的占位认证项，密码由随机 `stats_secret` 以独立域 HMAC-SHA256 派生，既不是固定密码，也不写入用户、订阅或对外节点信息。配置稳定，不会每次生成都更换密码并重启；有真实用户后只生成真实用户表。它不关闭认证，也不禁用协议。

验证：单元测试检查稳定、与统计 bearer token 不同、随密钥变化以及首个真实用户出现后的替换；真实 E2E 另外启动空用户服务器，检查其健康并要求普通账户凭据被拒绝，客户端与服务端仍运行。

### B18 — 下载失败被显示为无原因的 0.0，线程内异常不传播（中）

位置：`vps2vpn/bench.py:43–75`。原下载器捕获 OSError 直接结束工作线程，没有保留 HTTP 状态、Retry-After 或传输阶段；IncompleteRead 等 HTTPException 则只在线程里报错。主调用最终统一返回 0.0，无法区分限流、拒绝、截断、未完成预热与真实低速。

修复：保留有界错误信息、已接收字节及预热完成标记到 `download_diagnostics`，日志输出 HTTP 错误及 Retry-After，显式捕获不完整响应。成功/失败门槛不降低：E2E 仍要求每种协议有实际正下载结果。模拟 429/Retry-After 和 IncompleteRead 的回归覆盖错误归因。第二轮仅看到立即失败，第四轮补充诊断后已明确记录 HTTP 429 及 Retry-After=3600/3599。停止反复向该公共端点发送测速负载，不绕过其限流。

新增可选 `--origin`，默认公共端点保持原样。CI 在完成全部生产私网拒绝测试后，只在临时 E2E 配置为受控源的精确 loopback 地址/端口增加例外，重新启动三种真实核心，再要求每协议的单连接下载、四连接下载和上传均有正值、诊断无错误，服务端确实收到载荷。基准指定代理时使用显式 ProxyHandler，不能被 NO_PROXY 绕过；真实代理回归验证此点。CLI 仍保存部分结果 JSON，但测量不完整时退出 1。

Python 3.8 的新增 HTTPError 测试最初使用 fp=None，调用 close 时触发旧标准库内部 KeyError；改用真实 BytesIO 响应对象，且测试固定计时器，不依赖线程在毫秒内启动。生产关闭错误响应前也检查 fp。

## 尚未解决的事项与具体限制

### R01 — 普通用户重复赠送已修，历史周期与管理员预算变更仍需明确账本语义

旧路径可以复现：父账户 10 GiB 创建 9 GiB 子账户；子账户消费完自动停用；原 `deducting` 只看 active，使整笔 9 GiB 返还；父账户再次赠送。现在回归明确要求此时父有效额度只有 1 GiB、可分享为 0，再创建 9 GiB 码必须失败。

修复同时考虑祖孙：父给子 9，子给孙 7；子消费 1 后暂停，父仍承担 1 已消费 + 7 下游保留；孙消费 3 后也暂停，则只保留总计 4，返还真正未使用的 5。原零消费暂停返还语义保留。

以下属于管理员显式预算变更、历史迁移和非默认周期策略，不能混同于上述普通用户可自行触发的漏洞：

- 后续已修复 `delete_user`：删除时把可见后代消费中不超过原赠额的债务保留到邀请者计数，避免返还已用字节，不重复加入历史。管理员删除仍会拆除直接邀请关系；存续后代的未来预算仍须管理员决定，历史周期不能从现有计数完整还原。
- 管理员可手动清零、更改父子重置日或追加独立额度。当前 `used_up/down` 不是不可变消费流水，`invite_deduct` 也没有保存每笔消费对应的预算周期。独立重置日下可能出现保守扣留或迟延返还，需要产品层明确周期归属。
- 历史已删除子账户的消费无法由 `invite.used_by` 的 ID 字符串还原；兑换日期和父预算来源并未完整保存。不能用猜测数字回填过去周期。

后续完整账本至少需要：父预算周期标识、不可变消费与分配事件、暂停/删除释放规则、祖先赠额与管理员独立额度的归属、手动清零的明确信用事件，以及旧数据库迁移起点。目标不变量为：父自身消费 + 由该预算支付的后代消费 + 未使用保留额不超过该预算（采样/停用延迟另计）；不能因恢复/重置返还同一字节两次。需要同时验证跨月停机、不同重置日、重置与采样并发、删除后后代继续运行、备份回滚及旧数据迁移。当前限定修复不伪造历史，也不声称完成该周期账本。

### R02 — TUIC 多用户短连接归属仍为估计（中）

采样窗口中已经结束的连接没有可恢复的用户标识。余数守恒修复只确保不因取整、超时和旧权重人为制造错误，不能从全局总计反推出每个用户。需要带可靠 per-user 累计/事件接口的上游核心，或另一种可验证的数据面观测方式；用更复杂的经验分摊仍不能提供精确计费。

### R03 — 跨节点恢复和离线窗口仍有信息缺口（中）

旧子节点没有 epoch 时无法识别所有重置；新节点首次观测只立基线，不追收加入前的历史；远端账户删除前尚未采集的最后字节可能丢失。备份回滚使计数与 epoch 同时回到旧版本时，也不能保证永远识别所有回滚。当前事务修复解决的是单次本地入账与检查点一致性，不是分布式 exactly-once 证明。

### R04 — 证书生命周期仍有系统级验证缺口（中）

同进程锁不是跨进程证书对事务。IPv4-only 的挑战绑定已加限定回退及 mock 测试；后续修复 staging 隔离、证书链/私钥验证和域名身份一致性，并用本地 CA 做真实 TLS 回归。生产 ACME、证书模式切换与外部反代组合仍需要真实部署验收。自签与公网证书切换也可能改变客户端 pin，需要有明确认证的更新路径。

### R05 — 月重置、周期和调度需要独立边界测试（中）

后续已对重置/采样并发、暂停、全量先重置、恢复 ID 重排及提交前外部副作用增加回归并修复。`jobs.monthly_reset` 仍使用本机当前月和“本月日期达到 reset_day”的判断；跨月离线、手动更改重置日、新建账户的首次执行应进一步按明确账期语义测试。采样/同步/限额重载存在时间间隔，不能承诺精确到字节的实时硬截止。

### R06 — 其他工程边界

容量/吞吐设置未做跨网络测量，不调整没有收益证据的 QUIC 窗口。后续修复 nft 跳端口规则成组切换和实际页大小内存估算，并加入调用级回归；真实 nft 权限和非 4 KiB 页 VPS 尚需部署验收。纯 Python 密钥运算恒时性、告警在 NAT/多设备场景的误报、长尾 DNS/故障切换、Windows/macOS/移动端长期网络切换等未得到完整动态验证。备份包含凭据，必须继续按敏感数据管理。
