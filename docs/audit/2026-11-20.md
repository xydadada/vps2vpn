## 关键设计决策

- 严格拒绝有歧义的请求 framing，并关闭连接；不尝试猜测客户端意图。依据 [RFC 9112 §6.3](https://www.rfc-editor.org/rfc/rfc9112.html#name-message-body-length)。
- 成功认证只释放该次请求自己的预算预留，保留同来源其他身份的失败与在途请求；并发请求必须先占名额。此机制用于限制单来源爆破，并非分布式防护系统。
- 保留现有协议、订阅入口和固定内核版本，避免未经真实测试的版本升级改变互通性。
- 资源上限用于限制最坏消耗；未声称提高 VPN 吞吐量或降低网络延迟。
- SSH 首次接入仍是 TOFU；持久 known_hosts 解决的是之后的密钥变化检测，不声称首次接入已获外部身份验证。

## 跨仓库兼容性

客户端读取 `/s/<token>/api/me`、`/report` 等接口，会员/管理员原有 JSON 字段不移除。
Hysteria 2 分享链接的 `pinSHA256` 在客户端固定 mihomo 源码中进入 TLS 指纹检查；`insecure=true` 不等于取消该指纹检查。未对这条正确路径做无收益修改。
客户端的节点分组和健康上报重试修复与服务端保持兼容。它将会员 API 从 HTTP 订阅来源升级为 HTTPS，并保留有效端口；只复用同一面板主机的已保存 HY2/TUIC 证书 pin，无 pin 时正常验证 PKI，不关闭全局 TLS 校验。仅 REALITY 自签名面板等不能安全建立信任的情况仍会明确失败。

服务端新增的同步流量 epoch 为可选字段，旧主节点可以忽略它；新节点只能利用上报的 epoch 识别重置，旧节点或离线恢复的观测缺口仍见后端剩余事项。

## 剩余边界

- 自签证书部署仍提供 HTTP 订阅兼容路径，订阅 URL 与内容包含访问凭据。首次通过不可信网络获取订阅的风险仍存在；需要可信证书或可信传输分发订阅。此处不能在不改变现有客户端引导流程的情况下凭空建立信任。
- 后续已增加每请求 20 秒读取截止点，与工作线程及正文上限共同限制慢读；它不覆盖业务处理、DNS 和写响应的全链路总时限，见补充报告 S03。
- 多节点同步为周期性统计，协议内核重启/统计 API 的观测间隙不能精确追溯所有字节。没有声称计费级强一致。
- Windows 桌面交互、macOS 权限、Android 真机 VPN/TUN，以及真实跨公网丢包/断网切换必须单独验收；Linux 单元测试不能替代这些行为。
- 上游代理内核属于固定版本依赖。本次检查生成配置、调用边界和选定 TLS 实现，没有逐行审计整个上游代码库。
