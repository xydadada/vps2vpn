## Integration and remaining risks

1. **数据库事务依赖。** cluster.handle_sync/sync_one 使用共同补丁提供的可嵌套 `db.transaction()`。必须与数据库修复一起审查/测试，不能仅摘取此提交部署。网络请求放在 DB transaction 之外；事务只包持久状态。
2. **HTTP subscription bootstrap remains high risk.** 现有自签名部署会生成 HTTP 订阅链接。令牌和协议凭据可能被链路监听/修改。因现有客户端信任引导与迁移尚未完整实现，本轮没有单方面把所有旧链接改成 HTTPS 或加 skip-verify。建议可信证书优先，或用可验证的 pin/CA 带外交付并设计兼容迁移。`tools/bench.py` 的 HTTPS 现在严格验证，但显式 HTTP URL 仍是既有兼容能力。
3. **TUIC attribution remains approximate.** sing-box Clash API 没有原生 per-user 累计计数，采样间结束的连接只能按近期权重分配；不能把本次修复宣传为精确计费。需要稳定 epoch 和原生 per-user counters 才能消除跨重启/短连接归属不确定性。
4. **Rollback boundaries.** installer 恢复上一份 panel Python 代码并尽力 reload；core binaries、数据库 schema/data、systemd units、内核/防火墙和 swap 不作整体回滚。安装并发也尚无跨进程锁；core apply 新锁只覆盖同一 Python 进程，CLI 与服务进程之间仍需 OS 锁或单一应用入口。
5. **Supply chain.** 既有 Xray/Hysteria release checksum 和 sing-box 固定 hash 机制保留。前两者下载与校验文件共享同一信任域，panel 默认下载 mutable branch；并非独立签名验证。建议发布不可变版本、验证签名/证明并做分阶段升级。本轮没有盲目升级锁定 core，避免已知客户端版本兼容回退。
6. **SSH trust.** 首次连接仍为 accept-new TOFU；持久记录可检测以后换钥，但旧版本未保存的主机首次迁移仍需可信渠道核实。合法重装换钥会明确失败，应由用户核实后更新记录，不自动删除旧 pin。
7. **Certificates.** ACME pair 仍是两个分别原子写入的文件，跨进程并发读/更新可能遇到短暂配对窗口；证书加载/信任检查会失败关闭，但要彻底避免窗口需目录 generation 或统一锁。公开 CA 可用性受操作系统 trust store 影响。未测试 ACME 失败恢复/端口 80 冲突全场景。
8. **Monitoring/AI heuristics.** 公开匿名 endpoint 的状态无法保证账户级访问；region 列表会变，挑战页、限流和服务器端与终端链路差异仍存在。系统 DNS getaddrinfo 没有被 Python socket timeout 严格覆盖，慢解析线程可能迟归；不承诺硬实时 monitor deadline。
9. **Routing boundary.** Xray private destination 修复基于 pinned dispatcher 源码与官方 routing 机制。需要在 core 配置检查/真实 DNS rebinding、IPv6、UDP 情况下验证；其他 core 的完整 ACL 实现、上游内核及第三方软件不在逐行审计覆盖声明之内。
10. **Node reports/credentials.** 主节点掌握同步用户密码，节点 secret 代表委托信任；本补丁不改变这一架构。line reports 为每用户每线路一条，成功清除、失败续期、24 小时 TTL；没有基于 reports 自动换端口。根审计需继续检查节点 API 身份验证、secret 轮换与 UI 错误传播。

## Follow-up: transactional enforcement and first CI results

The following follow-up builds on integration commit 2142a3658900d5b99cf9b2dffdda9951f1a4d591.

- **OPS-22 / jobs.enforce:** The snapshot, monthly counter reset and enabled-state updates were still separate transactions. A traffic write after the snapshot could be erased by reset; an administrator's manual pause could be overwritten by a stale scheduler decision. The complete database phase now runs in db.transaction(). Log messages and Telegram alerts are accumulated and emitted only after commit, so network calls do not hold the database lock and rolled-back decisions do not send alerts.
- **OPS-23 / jobs._quota_order:** Reverse numeric IDs are not an invitation topology after a backup restore. Enforcement now traverses actual invited_by edges in iterative postorder. A restored child can be re-enabled before the parent's shared allowance is evaluated. Traversal visits cycles once and does not rely on Python recursion depth. This traversal change does not claim that all other membership calculations are nonrecursive.
- **OPS-24 / API errors:** The new strict node snapshot validator raised ValueError into the generic HTTP 500 handler. Invalid snapshots are now HTTP 400, preserving accounts. Regression includes malformed JSON, non-object JSON, missing users and invalid credentials.
- **OPS-25 / re-enabling Telegram:** Clearing both offset and token when command processing is disabled refreshes the startup timestamp when re-enabled; the last command received during the disabled period is not replayed.
